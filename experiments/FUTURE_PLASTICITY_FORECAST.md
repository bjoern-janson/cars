Question:

> **Can prospectively measured checkpoint state forecast how much a continually trained neural network's future trainability will differ from a matched fresh network on the same concealed future task?**

The benchmark is motivated by an independently established phenomenon: neural networks can lose plasticity under continual training, including on Online Permuted MNIST. This benchmark does not assume a novel explanation for that phenomenon.

## Neutral scientific object

For checkpoint state `S_t` and a future task transformation `E*`:

```text
Γ_t(E*)
=
future learning trajectory produced from S_t on E*
```

The first empirical question is only:

```text
P(Γ_t(E*) | measured S_t) ?
```

The future task is called a **future task transformation** or **future task condition**, not a corrective intervention.

No `Z`, MAGIKARP variable, correction capacity, recoverability variable, or adaptive-complexity variable is defined.

## Benchmark family

Use a computationally reduced Online Permuted-MNIST setup.

A task is generated by applying one fixed random permutation to the 784 MNIST input pixels. The same permutation is applied to every train/test example in that task. A new task uses a newly sampled pixel permutation.

The benchmark is not a literal reproduction of any prior paper's exact network size, task count, or online update schedule. Its scientific motivation is inherited from the established plasticity-loss setting; all quantities below are frozen for this benchmark before outcome generation.

## Network and continual history

One shared initialization is used across history runs so parameter coordinates are aligned across checkpoints.

```text
MLP
784 → 64 → 64 → 10
ReLU
SGD
learning rate = 0.05
momentum = 0
weight decay = 0
batch size = 128
```

Each history run receives a different sequence of Permuted-MNIST tasks.

```text
history runs = 12
maximum history age = 24 tasks
checkpoint ages = 1, 4, 8, 16, 24 tasks
```

Each history task uses a fixed 4096-example MNIST training subset and 1000-example test subset, transformed by that task's permutation. One pass over the training subset constitutes one history task.

The reduced dataset/task count is a compute-bounded benchmark choice. Failure to reproduce large-scale plasticity loss is an admissible negative outcome.

## Future-task concealment

The future task identity must not enter the checkpoint measurement process.

Operational order:

```text
train history to checkpoint
        ↓
measure checkpoint state
        ↓
freeze checkpoint measurements
        ↓
consume separate future-task RNG stream
        ↓
generate E*
        ↓
measure future learning
```

The future task permutation seed is prospectively fixed in the config, but the runner does not consume it until after checkpoint measurements have been produced.

This is procedural concealment, not a claim that the experimenter is metaphysically ignorant of the seed.

## Matched fresh-network control

For every checkpoint and exact future task `E*`, construct a fresh reference network:

```text
same architecture
same exact initial weights used before that history run
same E*
same future-task training examples
same future-task example order
same optimizer and learning rate
same training budget
```

Then compare:

```text
Γ(checkpoint, E*)
versus
Γ(fresh, E*)
```

This controls future-task difficulty directly.

The primary phenomenon is therefore **history-dependent future trainability**, not raw future-task performance.

## Future learning trajectory

For checkpoint and fresh reference, record test accuracy at normalized future-training fractions:

```text
0
0.125
0.25
0.5
1.0
```

The full trajectory is retained as `Γ`.

Two scalar primary summaries are derived.

### Primary 1 — ΔAUC

```text
ΔAUC
=
AUC_accuracy(checkpoint)
-
AUC_accuracy(fresh)
```

Negative values indicate less future-learning area than the matched fresh network.

### Primary 2 — T90 gap

Let:

```text
target accuracy
=
0.9 × fresh final accuracy
```

Define `T90` as the first normalized future-training fraction at which the model reaches that target. A model that never reaches it is assigned the prospectively fixed value `1.25`.

Then:

```text
T90_gap
=
T90_checkpoint
-
T90_fresh
```

Positive values indicate slower future learning than the matched fresh network.

These two summaries do not replace the retained learning curve.

## Checkpoint measurements

### Temporal baseline

```text
task_age
```

Age is included explicitly because a simple temporal trajectory may explain most future plasticity variation.

### Current capability

Measured on the most recent history task:

```text
current_task_accuracy
current_task_loss
```

### Established plasticity / trainability measurements

Prospectively freeze:

```text
parameter_l2
mean_abs_parameter
distance_from_initialization_l2
gradient_l2_on_probe
dead_relu_fraction
activation_effective_rank_fraction
activation_std
```

Definitions:

- `parameter_l2`: L2 norm of all trainable parameters.
- `mean_abs_parameter`: mean absolute value of all trainable parameters.
- `distance_from_initialization_l2`: L2 norm of current parameters minus the exact shared initialization.
- `gradient_l2_on_probe`: L2 norm of the cross-entropy gradient on a fixed-size probe batch from the current task.
- `dead_relu_fraction`: fraction of hidden ReLU units whose activation is zero for every example in the current-task probe batch, pooled across both hidden layers.
- `activation_effective_rank_fraction`: participation-ratio effective rank of the centered second-hidden-layer activation matrix divided by the maximum possible rank.
- `activation_std`: standard deviation of second-hidden-layer activations over probe examples and units.

These are ordinary network-state measurements. No claim is made that they exhaust established plasticity measures.

### Broader checkpoint-state adversary

A fixed 32-dimensional Rademacher projection of the **full parameter displacement from initialization** is computed at each checkpoint.

```text
parameter_delta
→ fixed random ±1 projection
→ 32-dimensional checkpoint sketch
```

The projection seed is frozen before outcomes.

This sketch touches every parameter but remains a finite generic representation. Failure of the sketch does **not** prove that the full checkpoint contains no additional predictive information.

## Forecast hierarchy

All predictors are evaluated out of sample with grouping by history run, so checkpoints from the same continual trajectory never appear in both train and test folds.

Outer evaluation:

```text
4-fold GroupKFold by history run
```

Ridge regularization is selected only inside the outer training set using:

```text
3-fold inner GroupKFold
alphas = 0.01, 0.1, 1, 10, 100
```

Forecast models:

```text
NULL
outer-training mean only

AGE
age only

CAPABILITY
age + current accuracy/loss

PLASTICITY
CAPABILITY + established plasticity measurements

RICH
PLASTICITY + 32-D full-parameter sketch
```

Each primary outcome is forecast separately.

Report:

```text
RMSE
MAE
R²
```

for all models.

## G0–G3 questions

### G0 — Forecastability

Does `RICH` improve held-out prediction relative to `NULL`?

Report:

```text
RMSE(NULL) - RMSE(RICH)
```

with a 95% group-bootstrap interval over held-out history runs.

### G1 — Current capability

Does `CAPABILITY` improve held-out prediction relative to `AGE`?

### G2 — Established plasticity measurements

Does `PLASTICITY` improve held-out prediction relative to `CAPABILITY`?

### G3 — Broader checkpoint state

Does `RICH` improve held-out prediction relative to `PLASTICITY`?

These are predictive comparisons only.

```text
predictive gain
↛ causal mechanism
↛ new construct
```

## Bootstrap

The out-of-fold prediction table is fixed first. Then resample complete history runs with replacement 2000 times and recompute RMSE differences for the prespecified model comparisons.

The bootstrap quantifies stability of held-out predictive differences across observed history streams. It does not repair model-selection bias or establish transport.

## Useful negative outcomes

```text
RICH ≈ NULL
→ future trainability not forecastable at this measurement/sample resolution

AGE explains most prediction
→ simple temporal trajectory sufficient at this resolution

PLASTICITY ≈ CAPABILITY
→ selected established metrics add little incremental prediction

RICH ≈ PLASTICITY
→ broad parameter sketch adds little incremental prediction
```

None of these outcomes imply that no other checkpoint representation could work.

## Useful positive outcomes

The strongest positive statement available in this pass is only:

> **Prospectively measured checkpoint state contains held-out predictive information about paired future learning trajectories on concealed Permuted-MNIST tasks beyond the comparator set tested.**

No stronger interpretation is authorized.

## Literature anchor

The benchmark is motivated by established plasticity-loss work using continually permuted MNIST tasks. Relevant examples include:

- Dohare et al., *Loss of plasticity in deep continual learning* / *Maintaining Plasticity in Deep Continual Learning*.
- Rohani et al., *Preserving Plasticity in Continual Learning with Adaptive Linearity Injection*.

These sources motivate the phenomenon and task family; they do not authorize any new construct here.
